# Portfolio Manager

Portfolio Manager tracks whole accounts belonging to named people, with separate platform accounts, holdings, currencies, source details and connection state. It does not allocate ownership shares. Manual Trading 212 orders are available only after the account owner authorizes trading for that connection.

Trading 212 is the first automatic connector. Its official API supports Invest and Stocks ISA accounts, using an API key and secret. The owner must authorize access and select read permissions for accounts and portfolios, plus History: Transactions for account returns and History: Orders / History: Dividends for historical reconstruction. Viewing requires no execution permission. Enter credentials only through the app’s connection form. The connector cannot independently inspect granted scopes; the broker checks each request. Other platforms support saved snapshots.

The page refreshes connected accounts every minute while visible using two client workers. A two-worker server sampler continues every 15 minutes when the page is closed. Both use shared server in-flight suppression and persisted per-account retry windows. A full summary and positions response must validate before replacing an account snapshot. Errors retain the last successful snapshot with its original fetch time. API fetch time is not a quote observation timestamp, and the two broker reads are not atomic. This is polling rather than a guaranteed real-time streaming feed. Empty successful positions arrays remove closed holdings. Demo accounts are explicitly labeled and excluded from combined totals; repeated broker account IDs within an environment are rejected.

Share prices use the instrument currency; holding values and returns use the primary account currency supplied by `walletImpact`. Cash includes available, order-reserved and pie cash. Realized trading P/L, unrealized P/L and a manually reported total return are separate fields. The connector does not manufacture net deposits, dividends, time-weighted returns, unobserved historical valuations or FX conversions. Allocation is based only on known position values, excluding cash. Currency totals use last available snapshots and disclose missing accounts.

## Data and operations

The private `portfolio.sqlite` database resides in `OPENING_BELL_DATA_DIR` alongside the existing databases. It uses WAL, file mode 0600 and revision-checked metadata/import writes. API credentials are encrypted using the existing authentication key with account-specific authenticated context. No credentials are returned to the browser or included in snapshot exports. All routes mount behind the existing owner authentication, origin and CSRF checks. Back up this database and `auth.key` with the other operational state; the general workspace export does not contain it. Snapshot exports preserve account financial data, but exclude people, account labels, connections and performance history. Historical samples and imported executions are retained only in the private operational database backup.

Users can add/rename/remove people and platform accounts, review/import a version-1 JSON snapshot, export an account snapshot, connect or disconnect Trading 212, and search holdings. Removing an account requires confirmation and also removes its performance history; snapshot export preserves only the current financial snapshot. Disconnecting deletes credentials while keeping the last snapshot. Import requires disconnecting first and always becomes a manual snapshot, regardless of the input’s source field.

Open return is shown as both an amount and a percentage of the cost of current holdings. The currency summary divides summed open return by summed cost, rather than averaging account percentages, and identifies coverage; missing costs withhold the percentage. Combined trading return adds the supplied realized and unrealized amounts. It is not the broker's all-activity total return, and no percentage is derived using open-position cost as a denominator for closed trades. A snapshot's reported total and percentage remain separate. Trading 212's [Portfolio Charts explanation](https://helpcentre.trading212.com/hc/en-us/articles/22435640547613-Portfolio-Charts) distinguishes open-position return from its money-weighted account performance, which includes cash flows and other activity not supplied by the connected account-summary/positions endpoints.

Click a holding to open the existing company details, financials, earnings, news and interactive chart with saved imported levels. A purple dashed average-paid line belongs only to the selected account/holding and uses its instrument currency. It updates with the account snapshot, is included in automatic price scaling, and can be hidden; a manually saved range can be restored to auto with Fit average price. It is never saved as a drawing, used by the strategy, converted into account currency or shown on another holding. Broker and Yahoo readings retain separate source/fetch information. The line waits for matching chart symbol and currency metadata.

Automatic matching supports primary USD AMD, AAPL, TSLA, GOOG, GOOGL, META, SOFI and NFLX listings with conflicting ISINs rejected. Trading 212's legacy FB identifier maps to META under the [issuer's documented ticker rename](https://investor.atmeta.com/investor-news/press-release-details/2022/Meta-Platforms-Inc.-to-Change-Ticker-Symbol-to-META-on-June-9/default.aspx). The legacy IPOE identifier maps to SOFI under [SoFi’s documented merger and ticker change](https://investors.sofi.com/news/news-details/2021/SoFi-A-Leading-Next-Generation-Financial-Services-Platform-to-Become-Publicly-Traded-following-Business-Combination-with-Social-Capital-Hedosophia-V/default.aspx). Holdings lead with the broker-provided company name and show a verified current ticker underneath; raw broker IDs and ISINs remain in expandable holding details. GOOG and GOOGL remain distinct share classes. Netflix maps directly to NASDAQ:NFLX using [Trading 212’s published ticker, exchange and ISIN](https://www.trading212.com/trading-instruments/invest/NFLX.US). QQQ and SPY map as funds on Nasdaq and NYSE Arca respectively. Other USD holdings with an exact `_US_EQ` identifier automatically use a single matching U.S. ticker/share class from the saved watchlist. Multiple exchange matches, conflicting known ISINs, other currencies and non-U.S. identifiers remain unresolved. The current watchlist supplies the exchange for these matches; no venue is inferred from Nasdaq-100 membership.

Automatically matched charts display their exact listing. Unmatched holdings still show account details and offer an explicit matching-listing choice from the saved watchlist for the current view. The picker starts empty, never at the first watchlist row. QQQ is a fund, not a choice of exchange for its component companies. There is no automatic venue or identity guess for unknown broker identifiers, including SPCX. Opening details or toggling the account overlay does not change the watchlist, imports, drawings or strategy selection; explicit chart controls retain the app's existing saved-settings behavior.

The empty JSON template is downloadable in the import dialog. Required fields are `version: 1`, a three-letter `currency`, and a `holdings` array. Each holding requires `ticker`, `name` and numeric `quantity`. Optional monetary fields remain null when missing; quantities retain up to eight decimals in the UI. `observedAt` must contain a timezone if known. Screenshots without a verified observation date keep it unknown; file modification times are not used as market timestamps. Use an exact broker instrument identifier or the screenshot’s label without guessing a market-feed mapping.

## Account performance and older history

The main account view defaults to MAX and shows account value, return, calculated money-weighted rate, net deposits, value history and cash. Trading-only totals remain under Return details. Complete, same-currency deposit and withdrawal history is required to calculate account return; dividends, interest and charges affect the account balance. Unknown funding types and currency conversions withhold unsupported results.

1D is a rolling 24 hours; 1W is seven days; 1M/3M/1Y use calendar lookbacks and YTD starts January 1 UTC. Without a full starting balance, two recorded balances inside the period provide an explicitly labeled partial return and rate. Deposits and withdrawals are excluded from profit. MAX uses account-wide return since funding began. Trading 212 does not supply its native historical account-value curve through these API endpoints.

**Older account history → Rebuild older history** reads complete orders, cash transactions and dividends, resuming pagination while the page is open. It anchors the scan to a recent broker snapshot and reconciles all shares and cash before publishing. Verified Yahoo daily prices reconstruct estimated balances at 16:00 New York each date, carrying the previous supplied close over non-trading days for up to seven days. Split-adjusted prices are restored to historical share units; dividend-adjusted prices are not used. Reconstructed points and period returns based on them are labeled estimated, with their actual baseline date. Their daily resolution and source prices can differ from the broker app. Recorded broker balances take precedence from the first recorded observation onward.

Current reconstruction supports ordinary trades in the primary account currency and verified U.S. listings. Corporate actions, transfers, foreign-currency trades, missing prices or failed cash/share reconciliation stop the rebuild with an explanation. Limits are 30,000 history records, 100 historical instruments and 20 years. Partial scans never replace a valid completed chart. This does not infer an exchange for unknown identifiers such as SPCX.

Valuations are recorded once per 15-minute bucket, plus the latest snapshot. After 90 days, daily observations and the first observation are retained. Funding and execution imports remain private and are tied to the broker identity/environment; account deletion removes their history. Reconstructed data is included in the private database backup, not the current-snapshot export.

## Manual Buy / Sell

Use **Trade / orders** on a connected account or **Buy / Sell** inside a holding. All new and existing connections start disabled. The owner needs Metadata, Orders: Read and Orders: Execute on the broker key and must explicitly enable trading for the selected account in this app. Replacing the connection requires enabling it again.

Search the broker’s exact stock/ETF catalog, choose Buy or Sell, enter shares, and select Market or Limit. Limit orders offer Day or Good until cancelled. This version supports matching instrument/primary-account currencies and share quantities, not order values, options, short sales or automated strategies. It checks broker identity, available cash and `quantityAvailableForTrading`; pie/reserved shares may be unavailable. Market estimates use a held instrument’s broker reference price where available, otherwise remain unavailable; the broker determines execution price. Market orders use regular hours only.

A single-use 60-second review freezes the exact account, LIVE/DEMO environment, instrument, side, quantity and limit. Confirmation revalidates broker balances (cached at most five seconds) before sending. Broker limits and additional fees still apply. A pending-order list supports a separately reviewed cancellation. A cancellation response acknowledges a request; disappearance from pending orders does not prove a fill or cancellation.

Order attempts are stored before sending to the fixed live/demo broker host. Reusing a consumed review never sends another order. A timeout, malformed reply, server error or interrupted process leaves an uncertain attempt and blocks another submission. The user must inspect Trading 212’s pending orders and trade history before marking it reviewed. There are no automatic retries of broker writes. Disabling trading or disconnecting does not cancel existing broker orders. No real orders or owner broker credentials are used in automated tests.

## Portfolio insights, journal and trading hours

**Portfolio insights → Combined exposure** groups known holdings by security and account currency, with each person’s position and concentration underneath. Demo accounts are excluded. Weights exclude cash and holdings without a value; snapshot dates and disconnected/manual sources remain visible. Share classes and instrument currencies stay separate.

**Price alerts** supports an above/below price crossing or entry into a saved supply, demand or gap zone for a connected holding with a verified Yahoo listing. Checks run on the server every minute, even with the browser closed. The first fresh quote sets a baseline; gaps over 30 minutes reset it. A rule fires once, creates an in-app notification in Activity & alerts, and can be re-armed. Saved zone prices and dates are frozen when the rule is created. Delayed quotes and polling can miss brief touches. No alert places an order or sends an external message.

**Trade journal → Broker trades** automatically lists confirmed stock executions, including separate partial fills. Reasoning and review notes are saved against the exact account and execution with revision checks. Broker refreshes preserve them. These records stay separate from manually matched options trades. Export this page downloads the current 50-row journal page, including notes.

**Monthly reports** shows each account’s recorded or reconstructed return, calculated money-weighted rate, executions, supplied execution charges, cash movements and cash distributions. Select a month and person, then export CSV or Print / PDF. Imports resume while the report is visible; History: Orders, History: Transactions and History: Dividends permissions are needed for their respective sections. Partial imports and valuation gaps are explicit. Reports never treat today’s value as a missing historical month end, invent missing fees, combine currencies, or subtract fees and distributions again from account-wide return. CSV exports preserve original values and neutralize spreadsheet formulas in text.

Holding rows, holding details and the trade ticket show a clickable **stock session dot**: green for the regular session, amber for pre-market/after-hours, purple for overnight, gray for closed or unavailable. The exact instrument’s `workingScheduleId` is joined to Trading 212’s exchange events; times follow the configured display timezone. Metadata read permission is required. Schedules refresh every ten minutes, respect broker backoff and become unavailable outside coverage or when stale. These are scheduled hours, not monitoring for halts or a guarantee that an order will be accepted. Market orders offer an explicit session choice. Newly selected eligible stocks default to extended sessions (24/5 where available); regular-only remains selectable. The server verifies instrument eligibility and freezes `extendedHours` in the reviewed order. Previously prepared orders keep their original setting. The API limit-order request has no extended-session parameter, so use Trading 212 directly to choose 24/5 for a limit order. Broker-reported session settings are shown on pending orders; missing settings remain unknown. Existing pending orders are not changed or replaced automatically.

The new caches, rules, distribution imports and journal notes are additive tables in the private `portfolio.sqlite` database. Back up this database with the existing runtime state. Account removal removes its related data; disconnecting pauses checks while preserving saved records.
